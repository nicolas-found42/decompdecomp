# PS2 toolchain and SDK integration on Apple Silicon

Research date 2026-11-18. The local source baseline is `4b183795da198b9a2bafb8f19e8306b374d8e983`. Every addition needs to run end to end on an Apple Silicon Mac. Built-in helpers and manual project-scoped MCP clients both need to be able to discover and use the current and added PS2 capabilities. The research inspected source, unpacked the two SDK installers on a Mac, and compared the compiler payload with the pinned public pack. The benchmark and tool-access results are recorded below.

## Recommendation

Start with a local SDK library index. The supplied disc's production EE compiler and assembler binaries match the shipped `040921` compiler pack. Its 100 EE archives are the more promising new input. Extend the existing SDK lookup to report archive member provenance and test its precision alongside the current signature database. For compiler expansion, favor one distinct build or compiler/assembler pairing with a demonstrated improvement. Hold the C, header, flags, and function boundary fixed and measure the candidate against the installed profiles. The existing [PS2 matching investigation](ps2-matching-tools.md) covers decompilers, flag searches, and the permuter.

## Decisions from the design interview

- **SDK setup and lookup.** Register extracted SDK library folders in **Compilers & tools**. Each PS2 project chooses which registered SDKs to search. Selecting an SDK starts a low-priority scan of imported functions, including mapped overlays. Cache the results until the SDK or function evidence changes. Surface relevant results in briefs and `ps2_sdk_symbols`. Return candidate names, addresses, provenance, and supporting evidence. SDK files and raw library bytes stay local. In rooms, the host selects the SDKs, runs lookup, and approves names.
- **Name review.** Helpers and manual MCP users can inspect and propose names. The owner approves them in the desktop app. Bulk approval requires an unambiguous candidate, agreement on the function boundary, and at least one corroborated relocation. Conflicting names, short stubs, and missing or unresolved relocations need individual review. Keep name approvals and evidence in saves. Remember dismissals until the evidence changes. The linked-byte judge remains the authority for C matches.
- **Tool access and jobs.** All applicable current and new capabilities are available to built-in helpers and manual MCP users. After the owner enables background jobs for a project, both can start SDK assembly verification and Deep permuter with the desktop jobs' effects. Interactive and helper compiles have priority. Allow one active and one pending heavy job per project, reuse the job for a duplicate request, and share status and cancellation. Start a queued job's budget when it begins. A restart ends the jobs and keeps any saved improvements.
- **Deep permuter handoff.** Helpers can start a search when the remaining differences look like register allocation or instruction order. A manual client can request one for any eligible function. At startup, use the latest saved, scored C. A helper can hand off its own claim when the search starts. Close an ineligible queued request with an explanation before it uses its compile budget.
- **Release evidence.** Compare both SDK scanners on the same boot functions in a scratch copy of GT4. Report overlay results too. Require at least one independently confirmed identification the existing scanner misses and zero wrong high-confidence identifications in the reviewed benchmark. Use a separately recovered symbol or manually checked calls and data references to corroborate a new hit. Record also the ambiguous hits and scan time. Verify real calls on Apple Silicon from a managed CLI helper, the API helper, and a manual MCP client. A later compiler profile needs a repeatable exact match on Apple Silicon that the current profiles miss. Local translation is acceptable.

## What the app already does

- The PS2 ROM connector registers 11 built-in profiles across Sony EE-GCC, SN Systems GCC, CodeWarrior, and mixed compiler/assembler combinations. Setup already offers **Your own PS2 compiler** for folders that fit a pinned pack's layout and command. The kit recognizes versions from the compiler or nearby front ends. The local ID uses a truncated hash of the driver alone, so a matching ID does not establish the identity of every participating binary. [PS2 connector](../src/decompnet/consoles/ps2/__init__.py#L30-L66), [own-compiler kit](../src/decompnet/kits/owncompiler.py#L77-L114).
- On Apple Silicon, the pinned Linux i386 EE-GCC packs have local iSH and Colima routes. The pinned Mac wibo route for SN GCC and CodeWarrior requires Rosetta. An own-compiler profile that needs the Linux runner hits an explicit guard before tool preparation. Both guest preparation implementations assume staging, and iSH additionally expects pinned archive metadata. Giving the existing kit a new directory layout alone cannot make a Linux kit compile on this Mac. The guide's statement about Linux-only period compilers predates the documented Mac runners. [Mac runner guide](linux-compiler-vm.md), [wibo pin](../src/decompnet/toolchains.toml#L851-L868), [kit guard](../src/decompnet/project.py#L44-L64), [iSH staging](../src/decompnet/ish_runner.py#L35-L58), [VM staging](../src/decompnet/linuxvm.py#L183-L222), [user guide](GUIDE.md#installation-details).
- The app already exposes Ghidra Emotion Engine, PS2Recomp SDK signature scanning, and companion-ELF symbol transfer. It also verifies selected kernel assembly against pinned public PS2SDK sources. ROM C matches require linked byte equality without link problems. Community projects use their own build and objdiff. Use the existing judge for compiler experiments and keep SDK names as candidate evidence in briefs. [PS2 analysis guide](GUIDE.md#platforms), [assembly verification](../src/decompnet/consoles/ps2/ps2sdk.py), [ROM byte judge](../src/decompnet/rom/match.py#L342-L393), [community project judge](GUIDE.md#public-decomps).
- `compare_compilers` tests the assigned profile and up to two named alternatives on the same C. The bulk comparison already enumerates usable installed profiles and factors the source, header, target and profile list into its cache key. The compiler-map survey uses only the project default and assigned ranges, with a source-only skip key. Installing another profile alone will leave it outside the survey unless it is assigned. Start controlled comparisons through the existing tools before changing automatic selection. ## What the supplied SDK proves

A local listing identified a 981,008,384-byte ISO named `PlayStation 2 July 2005 SDK (version 3.0.3).iso`. The checksum-verified ARM64 release of WiseUnpacker 3.1.0 ran on this Mac and unpacked `RTLibs&ToolchainSetup.exe` and `SoftwareToolsSetup.exe` inside a scratch directory with network access disabled. Both installers were parsed as data. [WiseUnpacker release](https://github.com/mnadareski/WiseUnpacker/releases/tag/3.1.0).

| Local result | What it supports |
| --- | --- |
| `ee/gcc/bin/ee-gcc`, `ee-g++`, `ee-as`, `cc1`, and `cc1plus` are Linux i386 ELF executables. All five compare byte for byte with their counterparts in the checksum-verified `ee-gcc3.2-040921.tar.xz` that both pinned 3.2 profiles use. | The disc supplies the same five executable components. The installed profiles use distinct command recipes. |
| The ISO additionally contains `ee-ld` and a GCC `specs` file that are absent from that archive. | The full SDK and its command environment have differences worth controlling if we test SDK-based linking or compare compiler behavior. |
| The EE subtree contains 100 `.a` files. Sampled `libkernl.a` and `libtimer.a` have 30 and 5 little-endian MIPS ELF relocatable objects respectively. | Specific archive members are a source of symbols, relocation records, and function evidence for the local scanner. |
| The disc has a separate Linux i386 IOP compiler. It also has Linux i386 and Win32 versions of VCL. | These target IOP or vector-unit work. A matching-EE use case and a working Mac runner would need independent proof before adding them. |

The comparison read the named members directly and verified the public archive against the digest in the toolchain registry. No SDK executables were run. The existing `own-ps2` directory picker does not accept an ISO and the Mac Linux runner blocks the extracted EE compiler as a user kit. A local library reader can use the archive objects directly on the Mac. A future compiler-kit feature needs an in-place route or a change to the repository's kit contract. [040921 pack and recipes](../src/decompnet/toolchains.toml#L308-L323), [standard driver](../src/decompnet/toolchains.toml#L374-L389), [kit conventions](../CONTRIBUTING.md#adding-a-kit-a-compiler-or-sdk-users-bring).

## What the linked projects add

- **Compiler reproducibility.** RetroReversing's index and source point to real matching builds. The Digital Devil Saga project documents differences produced by modern assemblers and pins its runtime around period EE-GCC 2.96. Its tools contain exact-input and exact-output hash checks for changes to `cc1` address placement and the old assembler's overlapping-copy behavior. Reproduce a varying output on the Mac before considering either change. A patched profile would need its own ID, provenance and baseline comparison. [RetroReversing PS2 index](https://www.retroreversing.com/ps2), [index source](https://github.com/RetroReversing/retroReversing/blob/master/categories/consoles/PS2.md), [DDS toolchain notes](https://github.com/Megami-Decomps/dds-decomp/blob/18d1fa88fdf086b8dad3f4c5cc331b5fcf917f36/docs/toolchain.md), [compiler patch](https://github.com/Megami-Decomps/dds-decomp/blob/18d1fa88fdf086b8dad3f4c5cc331b5fcf917f36/tools/ee_gcc_aslr.py), [assembler patch](https://github.com/Megami-Decomps/dds-decomp/blob/18d1fa88fdf086b8dad3f4c5cc331b5fcf917f36/tools/ee_as_relax.py).
- **A specific missing compiler build.** ChronicleTwo's PS2 build uses CodeWarrior `3.0-011126`. The local catalog has `2.3.3` and `3.0.1`. ChronicleTwo also configures Satan's Fiddle for compiler history and floating-point scheduling. Its setup establishes a concrete lead for that build, with Apple Silicon compatibility and access to a user-provided copy still to prove. Test the unmodified compiler through the app first, then evaluate the wrapper for a measured mismatch. [ChronicleTwo build](https://github.com/TheMoonPeople/ChronicleTwo/blob/bcd1967255b238c745cb7f6ac085e2119207a60a/ps2/CMakeLists.txt), [wrapper configuration notes](https://github.com/TheMoonPeople/ChronicleTwo/blob/bcd1967255b238c745cb7f6ac085e2119207a60a/docs/SATANSFIDDLE.md), [local CodeWarrior catalog](../src/decompnet/toolchains.toml#L391-L423).
- **Better function briefs.** The Puyodead1 fork at `99d83945740a1382e1c57e4365349a1b23c71cc6` has seven PS2 compiler entries, all present in this checkout. Its useful leads are fixes for generated C++ declarations and richer line and scope information. Evaluate those with a symbol-bearing PS2 fixture first. CCC is also an option for extracting useful declarations from `.mdebug` or other supported symbol data, with a native Mac build still to validate. Test attribution against homemade archives with known symbols, including identical functions in different members and relocation-bearing functions. ## Access for helpers and manual MCP users

- Built-in CLI helpers and manual MCP connections both authenticate to the same project-scoped server. The in-process API helper builds its schema from the same `project_tools` list and calls the same handlers. All three existing PS2 analysis tools and the ROM compiler trial and comparison tools already have both entry points. `project_info` lists compiler IDs from the console catalog, including kit IDs. It currently gives little help distinguishing ready profiles from profiles that need a runner or installation. [Server auth and discovery](../src/decompnet/app/server.py#L80-L92), [scoped tool listing](../src/decompnet/app/server.py#L143-L180), [shared tools and API invocation](../src/decompnet/app/tools.py#L426-L490), [API helper](../src/decompnet/agents/api.py#L100-L175), [compiler list](../src/decompnet/app/tools.py#L261-L275).
- The existing access policy can hide optional tools. PS2 analysis and `compare_compilers` are currently ROM-only. **Verify SDK assembly** and **Deep permuter** have app-window job routes. Their current workflows do not have corresponding callable helper tools. Audit current PS2 capabilities as part of the first delivery. Expose useful operations through the shared handlers and scoped MCP, with explicit readiness. For project-wide jobs, define how a helper can request a bounded run and how the owner approves or enables it. [Tool policy](../src/decompnet/app/tool_policy.py), [mode filtering](../src/decompnet/app/tools.py#L374-L441), [SDK verification job](../src/decompnet/app/routes/projects.py#L225-L238), [Deep permuter job](../src/decompnet/app/routes/projects.py#L318-L346).
- Give helpers a reason to call each capability. Start with SDK lookup for suspected library code, Ghidra or companion transfer for missing semantics, and compiler trials when saved C has a plausible compiler-sensitive difference. Add those cues to briefs and the PS2 guide. Prove use with a managed CLI helper, the API helper, and a separate manual MCP token on a scratch Mac project. Check discovery, a real invocation, usage records, and refusal from a different project. Keep SDK archive selection in Setup and identify approved inputs by ID in agent calls. [PS2 helper guide](../src/decompnet/consoles/ps2/guides/ps2.md), [manual MCP tests](../tests/test_manual_mcp.py), [tool tests](../tests/test_tools.py).

## Verification

### GT4 archive lookup benchmark

The Apple Silicon scratch copy had 1,147 imported functions, all in the boot program's mapped segment. The baseline signature scanner reported 335 addresses in that same catalog. The new reader indexed 8,513 named functions from 67 archives in the SDK's `ee/lib` folder. The cold index took 3.58 seconds and the in-memory comparison took 0.06 seconds. It found candidates for 570 functions. The baseline had no result at 296 of those addresses, and 138 results had multiple archive candidates. All 18 results with complete, unambiguous boundary and positive relocation evidence agreed in name with the existing scanner. Sixteen additional complete and unambiguous results also agreed with the baseline and require individual review because they have no relocations.

One independently confirmed new result is `sceCdChgSys` at `0x01015420`. Its full 36-byte body matches the SDK archive member after accounting for three relocation fields. The original function has a call paired with a load of a diagnostic string. Following the address in the linked ELF read that string from the original game and confirmed that it names `sceCdChgSys`. The current scanner reports no hit at the function's address. The candidate went through individual review because the SDK object has unnamed data relocations. The desktop approval endpoint applied the name in the scratch project, rechecked all 815 existing matches, and included the review evidence in the save manifest. These checks used database backups and a separate project directory.

The scratch project's companion ELF was present as an analysis input, and the project catalog contained zero mapped overlay functions. A homemade overlay fixture checked two functions at the same virtual address with separate ROM offsets. The app returned each one's own archive evidence and applied the host's approved name only to its physical function.

The same C reconstruction of the confirmed routine matched through the ordinary linked-byte judge under six existing profiles. This case supplies evidence for the library lookup and already has compiler coverage.

### Tool access and Apple Silicon

An authenticated manual MCP client ran the real SDK lookup, name proposal, Ghidra and companion analysis, all 11 compiler profiles via `try_compiler`, compiler comparison, flag search, the compiler map, SDK assembly verification, and Deep permuter. A managed CLI subprocess fixture used its managed token and the real MCP transport. A scripted API model called the shared handlers in-process. Both used actual SDK lookup, analysis, compilation, and background jobs on the scratch project. The fixtures exercise callability and execution without a live model account. The opt-in Mac engine suite passed the C, C++, negative match, and object-output tests for all 11 profiles.

For a future compiler candidate, compare executable hashes and record the runner, exact arguments, and object format. Check Setup with the runtime present and missing. Repeat the ordinary engine and export checks and compare a fixed set of saved attempts against the installed profiles. Record new exact matches, compile failures, and elapsed time. [Mac runner tests](../tests/test_ps2_compilers_macos.py), [PS2 matching tests](../tests/test_ps2.py), [contributor workflow](../CONTRIBUTING.md#adding-a-compiler-to-a-console).

The additional web research used Keenable. Firecrawl returned an invalid or revoked API key error.
